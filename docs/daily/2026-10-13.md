# 2026-10-13: Integration surface (infrastructure only)

Decision: Proof Desk stays infrastructure. Platforms build their own screens on our API, SDK, MCP and A2A. Today's work makes that easy.

## 1. Embeddable verdict widget
- **Where to get it:** every report link (`POST /v1/agreements/:id/report-links`, SDK `createReportLink`) now returns `embed.html`, a script tag plus a `<div>`, and `embed.iframe_url`.
- **The loader** (`/embed/v1.js`) swaps the div for an iframe of `/embed/r/:token`, which sizes itself to fit.
  - The iframe shows the title, the outcome, who decided and when, each check's verdict, and a link to the full report.
  - Light, dark or auto theme.
- **Framing:** only `/embed/*` may be framed; every other page still sends `X-Frame-Options: DENY` and `frame-ancestors 'none'`.
  - The embed page has its own strict CSP: no form actions, scripts only from Proof Desk.
  - No documents or evidence are shown. The same expiring token as the report link is required.
- **Tests:**
  - API: snippet, framing headers, nothing private, expired link, loader served cross-origin.
  - Browser: a mock marketplace on another port embeds the widget. It renders, resizes, and opens the full report in a new tab, with no console errors.
- **Docs:** `docs/integrations/embed.md`.

## 4. Self-serve sandbox sign-up
- **How:** `/signup` (a page) and `POST /sandbox/signup` (JSON, for scripts and agents) create an account with a **test-mode** key. It's shown once; we keep only a hash.
- **Live keys** are still set up by Proof Desk.
- **Safeguards:**
  - 5 sign-ups per IP per hour.
  - Self-serve accounts get daily quotas on what costs money: 100 verifier runs and 20 AI spec drafts per 24 h. Over the limit, the request is refused (`429 sandbox_quota_exceeded`) before any cost is incurred.
  - `SELF_SERVE_SIGNUP=off` turns sign-up off.
- **Tests:**
  - API: the key works and can't reach ops; input validation; rate limit; the off switch; the quota caps a sandbox but not provisioned accounts.
  - Browser: sign up, then sign in to the dashboard with the new key.
- **Also fixed:**
  - The embed commit had left the API-docs completeness test failing. HTML pages (`/embed`, `/signup`) are now excluded like the other pages, and `POST /sandbox/signup` is documented.
  - The sign-up form's labels weren't linked to their inputs (accessibility).

## 6. API key management
- **`/v1/api-keys`:** list (no secrets; `current` marks the calling key), create (named, shown once), roll, and revoke.
  - **Roll:** issues a new key with the same name and scopes; the old key keeps working for a grace period (default 24 h, max 7 days, 0 = revoke now).
  - **Revoke:** you can't revoke the key making the request; roll it instead.
- **New "verify" scope:** these keys can use only the Verify API, A2A and templates. They can't touch agreements, money or other keys, and can't sign in to the dashboard. It's the key to hand to an agent.
- **Guardrails:**
  - Creation never grants more than the caller has: no ops keys from platform keys, no live keys from test keys (a live key may create test keys).
  - Expired and revoked keys fail auth, and their dashboard sessions end.
- **Also in:** the TypeScript SDK (`pd.apiKeys`), the Python SDK (`pd.api_keys`) and the API reference.
- **Tests:** 5 API tests (scoping, verify-only limits, escalation refused, roll with a grace period then expiry, revocation rules) and the Python integration test. Migration `0016_api_key_management`.

## 7. Webhook tools and events
- **Test-send:** `POST /v1/webhook-endpoints/:id/test` sends a signed `webhook.test` event now and reports the receiver's status, error and timing.
- **Replay:** `POST /v1/webhook-endpoints/:id/replay {from_event}` re-sends from that event onward, in order. It re-enables an endpoint disabled after 20 failures.
- **Events list:** `GET /v1/events?after=&limit=&type=` returns the same events webhooks deliver, for backfill or polling. Scoped to the account, with `next_after` for paging.
- **Event catalog:** `docs/integrations/events.md` lists every event type, its payload fields and the tools. Linked from the marketplace guide.
- **SDKs:** TypeScript `webhookEndpoints.test/replay` and `events.list`; Python the same.
- **Tests:**
  - API: the test event verifies with the SDK; a failing receiver is reported; replay re-sends the same event ids and re-enables; events page and filter; other accounts get 404.
  - Python integration lists events.

737 Vitest + 6 Python tests passing.
- **Bug found by the Python integration test:** the events `type` filter stripped `_` (meant to neutralise SQL wildcards), so full names like `agreement.approve_spec` matched nothing. It now escapes `%`, `_` and `\` properly. The API test covers full names and a literal `_`, and fails without the fix (checked on PGlite and Postgres).
