# 2026-10-08: Part 7, stablecoin rail

## Shipped
- **Contract `contracts/src/ProofDeskJobs.sol`** (Foundry, Solidity 0.8.30). It implements the ERC-8183 core interface (`createJob`, `setProvider`, `setBudget`, `fund`, `submit`, `complete`, `reject`, `claimRefund`, `getJob`) for one stablecoin (USDC).
  - Proof Desk is only the **evaluator** address and never holds funds. The most it can do is settle a funded job between that job's own provider and client.
  - Extensions:
    - `createAndFund`: the client posts the agreed price and funds in one transaction.
    - `createAndFundWithAuthorization`: the same, but gasless via EIP-3009 `receiveWithAuthorization`. The nonce is derived from the job terms, so a signature funds exactly one job and can't be redirected or replayed.
    - `settle(jobId, releaseBP, reason)`: release, refund or split, from Funded or Submitted, so sellers never send a transaction.
  - Rules:
    - The fee is capped at 5% and locked into each job when it's created.
    - The provider can't be paid after expiry.
    - `claimRefund` after expiry works for anyone and calls no hooks (hooks are unsupported), so it can't be blocked.
    - Fee-on-transfer tokens are refused.
  - **Tests:** 20 unit and fuzz tests, plus 4 invariants (256 runs × 64 calls, every party including an attacker):
    1. Funds are conserved: the contract holds exactly the live budgets, and nothing is created or lost.
    2. Only the evaluator ever decides a funded job.
    3. The provider is never paid after expiry.
    4. Every expired funded job can be refunded in full, by anyone, at any time.
  - A planted bug (the evaluator check removed) is caught by invariant 2.
- **`packages/chain`:**
  - `ViemChainGateway` (viem 2.57): reads job state; finds the job a funding transaction created; relays gasless funding; settles. Reverts become non-retryable `ChainError`s, and RPC trouble stays retryable.
  - `FakeChainGateway` mirrors the contract's rules, including real EIP-712 signature checks.
  - The ABI and bytecode are generated from the forge build (`npm run contracts:build`; CI checks they're current).
  - `anvil.test.ts` deploys the real contract to a local chain and runs wallet funding, gasless funding, a partial settle with exact balances, revert mapping, and a check that the TS nonce equals the contract's.
- **API:**
  - `PUT/GET /v1/sellers/:ref/wallet`: the seller's USDC payout address.
  - `POST /v1/agreements/:id/onchain-job`: issues fixed terms.
    - provider = seller wallet; evaluator = Proof Desk.
    - description = `proofdesk:v1:<agreement>:<spec hash>`.
    - expiry = delivery deadline + 1 day + appeal window + 7 days.
    - Returns the two wallet calls, plus EIP-712 typed data when `client` is given.
  - `POST …/onchain-job/confirm {tx_hash}`: reads the job back from the chain and requires every term to match (provider, evaluator, description, budget, expiry, contract). A unique index stops one job from backing two agreements.
  - `POST …/onchain-job/authorization`: relays the buyer's signature. Proof Desk pays the gas.
  - Funding after the delivery deadline is refunded on-chain immediately, the same way late card holds are cancelled.
  - **Settlement:** `settle` is sent with the decision's **ledger entry hash as the on-chain `reason`**, so each on-chain outcome points back to the audit trail. Retries are safe: a job that already ended consistently is just recorded.
  - **Scheduler:**
    - Settles early (forced) when a decided job is within 24 h of expiry.
    - Warns ops (`onchain_expiry_near`) when an undecided one is.
    - Records jobs the buyer reclaimed (`onchain_expired`); only a refund decision can settle those.
  - **Payment links with `rail: "onchain"`:** a hosted USDC page (EIP-1193 wallet, one gasless signature; manual calls as a fallback) and **x402** at `/pay/:token/x402`. The x402 flow: 402 with requirements, then `X-PAYMENT` with the signed authorization, then relayed, then 200 with `X-PAYMENT-RESPONSE`. The scheme is `erc8183-job`: a `ReceiveWithAuthorization` to the job contract with the terms-bound nonce. Standard x402 "exact" clients sign `TransferWithAuthorization` and would need this scheme added.
  - Card and on-chain funding are exclusive per agreement.
- **SDK:** `sellers.setWallet/retrieveWallet`, `agreements.createOnchainJob/confirmOnchainFunding/authorizeOnchainFunding/retrieveOnchainJob/createPaymentLink/createReportLink`.
- **MCP:** `fund_purchase_with_usdc` and `submit_usdc_authorization`.
- **`npm run chain:e2e`:** the whole API flow against a real chain. Run on local anvil: funded gaslessly; partial 60% settled; seller received exactly 588,000 (0.588 USDC = 60% − 2% fee); buyer's net cost 600,000; ledger intact.
- **CI:** checks out submodules, installs Foundry, runs `forge test` (ci profile: 512 × 128) and the ABI freshness check.

# 2026-10-08: Part 8, verifiers #2 (code) and #3 (data/research)

## Shipped
- **Shared decision policy** (`packages/verifier/src/policy.ts`), used by all three verifiers.
  - A deterministic pass now stands on its own when no model was asked, e.g. the criterion's tests all passed.
  - New `gaming` flag: evidence that a delivery games the checks escalates to a human.
  - Reports share a `BaseReport`. Code and data reports add `tests` and `data` sections.
- **Code verifier** (`verifyCode`):
  - **Workspace:** the delivery is written first, then the buyer's inputs (tests, fixtures) on top, so a delivery can't replace or weaken the tests.
    - Tampering, unsafe paths, size limits and injection phrases are flagged.
    - Network, process, env and `eval` APIs are flagged when the task doesn't call for them. A stealthy, swallowed exfiltration attempt still passes the tests, so these go to a human.
  - **Sandbox:**
    - `DockerSandbox` for production: `--network none`, read-only root, `--cap-drop ALL`, `no-new-privileges`, uid 65534, memory/CPU/PID limits, optional gVisor (`DOCKER_RUNTIME=runsc`).
    - `NodePermissionSandbox` for dev and CI: Node's permission model, verified here to block reads outside the workspace, writes, child processes and network. The env is scrubbed. Node calls it a seatbelt, not a security boundary, so production defaults to Docker.
  - **Results:** Node TAP and Python unittest are parsed. Tests tagged `[criterion-id] …` count toward that criterion; untagged ones count toward the "tests" criterion.
  - **Hard fails:** timeouts, runs with no results, and failing tests no criterion covers all refund (override).
  - **Model judge** (`code-review/1`, Sonnet): reviews only what tests can't settle, and looks for code that special-cases the tests. The quote has to exist in the code before it counts.
- **Data/research verifier** (`verifyData`):
  - **Parsing:** JSON, JSONL, CSV (RFC 4180), or a markdown report.
  - **Schema:** the buyer's JSON Schema (2020-12, ajv + formats; CSV values coerced), `minItems` reported as too few records, `x-unique-keys` for duplicates, and "at least N" read from criteria.
  - **Research:** every cited URL must load, and every direct quote must appear in its cited source. Buyers can attach `sources/…` snapshots (`Source: <url>` first line) for paywalled pages.
  - **SSRF-safe fetcher** (`safeTransport`):
    - http(s) on standard ports only.
    - No credentials, localhost or `.internal` names.
    - Every resolved IP is checked **at connect time**, which also blocks DNS rebinding. Private, loopback, link-local, CGNAT, reserved and IPv4-mapped addresses are all refused.
    - Redirects are re-checked; time and size are bounded.
  - **Pass rule:** deterministic checks can fail any criterion, but only *pass* criteria whose check is "deterministic". A clean schema doesn't prove "accuracy".
  - **Model judge** (`data-review/1`): gets the source excerpts.
- **API:** `POST /v1/ops/agreements/:id/verify` (and the sandbox helper) dispatches by vertical.
  - Code and data verifiers are always on; their free layers need no API key, and the model judge joins when `ANTHROPIC_API_KEY` is set.
  - `CODE_SANDBOX=docker|node` (default: docker in production, node otherwise).
  - A missing test suite returns 422 `missing_tests`.
- **Dashboard:** the case page shows the test run (each test, pass/fail, message), schema errors, and cited sources with quote checks.

## Golden sets and results (free layers, no model)
- **Code:** `evals/code/golden.jsonl`, 110 items: 10 tasks × 11 variants.
  - Tasks: slugify, duration parsing, Luhn, Roman numerals, chunk, semver, word frequency, deep merge, CSV line, ISO week.
  - Variants: correct, bug, stub, hard-coded to public tests, syntax error, infinite loop, network escape, process escape, injection+correct, injection+bug, tampered tests.
  - The builder checks every reference passes and every bug fails. It caught one "bug" that was harmless on the test inputs, which was replaced.
  - **Results:** false release 0/80, false refund 0/80, critical recall 70/70, adversarial 60/60 never released, honest-delivery escalation 0%, p95 5 s.
- **Data:** `evals/data/golden.jsonl`, 50 items.
  - 4 datasets (JSON, JSONL, CSV) × 9 variants: valid, missing field, wrong type, bad format, too few, duplicate, truncated, injection, empty.
  - 2 research briefs × 7 variants: valid, dead link, fabricated source, misquote, SSRF citation to the metadata IP, too few sources, injection. These use an offline fixture web behind the same SSRF guard.
  - **Results:** false release 0/44, false refund 0/44, critical recall 100%, adversarial 12/12, honest-delivery escalation 0%.
- **Metric definition change (applies to all verticals, translation included):** the ≤15% escalation target is now measured on **honest deliveries**. Golden sets are attack-heavy by design, and escalating an attack is the right call. The all-items escalation rate is still reported, for information only.
- **CI gates:** all 50 data items and 22 code items (2 tasks × every variant) run on every push.
- **With credits:** `npm run eval:code -- --judge` and `npm run eval:data -- --judge` add a model-judged criterion. The GitHub "Verifier eval (model)" workflow now takes a `suite` input.
