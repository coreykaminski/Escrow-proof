# 2026-10-16: Zero-cost build list

## 1. Glossary checks for translation
- **How it works:** a buyer attaches `glossary.csv` (`source,target`; alternatives separated by `|`). Every glossary term that appears in the source must appear in the deliverable as an approved translation. Checked deterministically, with no model.
  - Matching is case- and Unicode-insensitive and allows up to 3 letters of inflection on the last word ("Contrato" matches "contratos").
  - Whole words only ("Agreement" doesn't match inside "Disagreement").
- **A miss** is a high-confidence `glossary_violation`. It fails the terminology criterion; it doesn't override the whole verdict when no such criterion exists.
- **Template:** `translation.document` takes `glossary: true`, which adds a critical `glossary-terms` criterion.
  - This fills the gap found on 2026-10-10: terminology errors had no criterion to fail.
- The glossary file is kept out of the source text the verifier compares.
- **Tests:** 4 unit tests (parsing, inflection, alternatives, case, word boundaries, unused terms). In the API, a translation using approved terms is released, and one using "Acuerdo" for "Agreement" is refunded even though the model layers raised nothing.

## 4. Developer pages in the dashboard
- **`/dashboard/developers`** (in the nav):
  - **API keys:** name, prefix, scopes, last used, status. Create a full or verify-only key (shown once), roll with a 24 h overlap, revoke (not the key of your own session).
  - **Webhook endpoints:** health (healthy, failing or disabled), last error and the last 5 deliveries. Add one (signing secret shown once), send a test event, replay from an event id, delete.
- **`/dashboard/events`:** this account's events, with a type filter and paging.
- **Shared rules:** key logic moved into `services/api-keys.ts`, so the API and dashboard enforce the same rules. The API key tests pass unchanged. Errors show as messages on the page; every form is CSRF-protected.
- **Tests:** 4 API tests (keys, webhooks, events, forged forms) and 1 browser test (create a verify-only key; it isn't shown again).
