# 2026-10-06: Part 1 Foundation

**Slice:** monorepo, CI, DB, API-key auth, agreement state machine, tamper-evident ledger.

## Shipped
- npm-workspaces monorepo (`packages/core`, `packages/db`, `apps/api`), TypeScript 7 strict, Biome, Vitest, GitHub Actions CI.
- Embedded Postgres (PGlite) for dev/tests, so no Docker. `DATABASE_URL=postgres://…` for real servers.
- Spec schema + hash-bound approval (an edited spec can't be approved with an old hash).
- Pure agreement state machine: 10 states, 11 events, actor permissions, deadline / appeal-window / dispute guards.
- Global hash-chained ledger: DB triggers block UPDATE/DELETE/TRUNCATE. The hash chain catches trigger bypass. Advisory lock serializes appends.
- Every transition plus its ledger entry is written in one transaction (`applyEvent`).
- REST API: platform routes (create/approve/fund/deliver/dispute/ledger), ops routes (verify/decide/resolve/settle/ledger-verify), Stripe-style idempotency, tenant isolation, test-rail-only-in-test-mode.
- CLI: `migrate`, `create-account`, `verify-ledger`.

# 2026-10-06 (afternoon): Part 2 Spec Engine

**Slice:** request → drafted criteria (Claude) → edit → approve by hash. AP2 mandate import stub. Eval harness for the ≥90% "testable" gate.

## Shipped
- `packages/spec-engine`:
  - `ClaudeSpecDrafter`: `claude-opus-5-5` (override with `SPEC_DRAFT_MODEL`), effort `medium`, structured output (Zod schema), server-side refusal fallback (`fallbacks: "default"`). Refusal, truncation and API errors map to typed `SpecDraftError`s.
  - Prompt `spec-drafter/1`: atomic pass/fail criteria with a `verification` method, check type and critical flag, plus `open_questions`. Request text is wrapped as untrusted data, and attempts to close the wrapper tag are neutralized.
  - `assembleSpec`: the model drafts only title, vertical and criteria. Money, deadline and appeal window always come from the caller. Criterion ids are normalized and deduplicated.
  - AP2 import (parsing stub): intent and cart mandates → request text, cart total in minor units, expiry check, mandate hash. Signatures are **not verified yet** and are recorded as `signature_verified: false`.
- Core: optional `verification` field on criteria (absent fields don't change existing hashes). `lintSpec` flags vague wording, missing verification, overlong criteria, no critical criterion, judge-heavy specs and single-criterion specs.
- API: `POST /v1/agreements/from-request` and `/from-mandate`. Agreements now return `spec_source` and `spec_warnings`. Provenance is on the ledger (`agreement.created.spec_source`), and edits mark a drafted spec `edited: true`. Migration `0002_spec_source`.
- CLI `draft-spec`. Server and CLI load `./.env`. `npm run dev` now runs from the repo root, so it shares `./.data/dev` with the CLI. Before this, `create-account` keys didn't exist in the dev server's database.
- `evals/spec-engine`: 50 requests (18 translation, 12 code, 10 data, 10 general, including vague requests and one prompt-injection attempt), `npm run eval:spec` → results, summary and review.csv, `npm run eval:spec:score`.

## Tests
- 292 passing (+54): lint rules, assembly/id normalization, AP2 parsing and currency digits, drafter request shape and error mapping (stubbed SDK), API flows (draft → edit → approve, terms validated before any model call, idempotent replay drafts once, retry after a transient failure, mandate amount rules, expiry, 503 without a key), CSV round-trip.
- Live smoke test: the server loads the key from `.env`. A real Claude call was **rejected with "credit balance too low"**, mapped to `502 spec_draft_failed`, and no agreement was created.

## Blocked / follow-ups
- **The Anthropic account needs credits** before the live drafter and eval can run. Then: `npm run eval:spec`, rate review.csv, `npm run eval:spec:score`. Gate: ≥90% testable.
- AP2 signature verification (user credential + merchant JWT) is deferred to when we integrate a real AP2 wallet/merchant.
- Drafting endpoints cost money per call, so they need per-account rate limits (Part 9, or sooner if exposed publicly).
- Prompt caching doesn't apply yet: the system prompt is below the minimum cacheable length.
