# Load test, 2026-10-15

Target: local server on embedded Postgres (pool 20), 8 CPUs, 8 GB. Each scenario ran 10s per concurrency level; latency is per operation, end to end over HTTP.

- **read**: GET /v1/agreements (authenticated list)
- **purchase**: create from template → approve → fund → deliver (4 writes, 4 ledger entries)
- **verify**: POST /v1/verifications: a 50-row CSV checked against a JSON Schema (no model)
- **public**: GET /ledger/checkpoint.json (Merkle tree head from stored subtrees)

## What it means

**Zero errors at every level.** The machine was also busy with other work during the run (load average about 8), so treat these numbers as a floor.

**Headroom against the plan:**
- The plan's $1M ARR target is about 15,000 jobs a month. That averages 0.006 jobs per second; a burst of 100× that is 0.6 per second.
- On one laptop-class machine we sustain about **170 full purchase flows per second** (create, approve, fund, deliver) and **60–70 automated checks per second**. That's roughly 250× the burst figure.
- **Reads and the public proof endpoints** serve 1,500–2,000 requests per second. Merkle tree heads come from stored subtrees (O(log n)), so they stay fast as the ledger grows.

**The first bottleneck is the single ledger lock:**
- Every state change appends to one hash chain under a Postgres advisory lock. Purchases peak at 8 concurrent clients, then slow slightly at 32 as clients queue for the lock (p99 about 0.5 s).
- This is the throughput ceiling the October outside review mentioned. It's far above current needs.
- **Revisit when sustained writes approach about 100 per second.** Options: batched appends, or per-agreement chains feeding the Merkle tree.

**Real checks are slower than this run:**
- Translation and the optional model judges call Claude, which takes seconds per check. They run outside database transactions, so they add latency but don't hold the ledger lock.
- Code checks are bounded by the sandbox host (one container per check). Size that host with the measured check rate in mind.
